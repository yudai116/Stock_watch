# SPEC_ADDENDUM_v2.md — 検証に基づく設計改訂と成果分岐フロー

> 本書は SPEC.md の改訂差分。矛盾する場合は本書が優先する。
> 改訂理由：エビデンス監査により、期待値を毀損する4欠陥（コスト・ショート・時間軸・最適化）を特定したため。

---

## R1. 執行手段の変更（最重要）

| 旧 | 新 |
|---|---|
| ロング＝CFD | **ロング＝Saxo現物株**（手数料0.08%・min$1、ファイナンスコストなし） |
| ショート＝個別株CFD | **ショート＝指数CFD（QQQ / SMH）のヘッジのみ**。個別株ショート廃止 |

理由：Saxo CFDのオーバーナイト金利は Offer Rate＋350bps（Classic）。金利4%環境で実効約7.5%/年が名目全額に日次課金され、2〜3週保有で名目の0.3〜0.4%/トレードのドラグ。個別株ショートは上方ドリフト・踏み上げ・変動借株料で構造的に不利。

実装影響：
- `execution/saxo_client.py` は現物株注文とCFD注文の両対応
- `signals/short_breakdown.py` → `signals/index_hedge.py` に置換（ベアレジーム時にポートフォリオβの30〜70%をQQQ/SMHショートで打ち消す）
- `backtest/costs.py`：ロング＝現物コスト（手数料＋スプレッド＋スリッページ、金利なし）、ヘッジ＝CFDコスト（スプレッド＋金利。ショートは金利受取になる場合もあるが保守的にゼロで見積る）

## R2. 時間軸の変更

- **シグナル生成・特徴量・レジーム判定はすべて日足**
- 1h足の用途は2つに限定：(a) エントリー執行タイミング（日足シグナル成立翌日、寄付き直後の乱高下を避けた執行）、(b) 場中ストップ監視
- 効果：取引回数減→コスト減、探索空間縮小→過学習面積減、データ量減→デスクトップでの反復高速化

## R3. 最適化方式の変更

- GAを主最適化から外す。**粗いグリッド（各パラメータ3〜5水準）＋台地選択**：
  - 目的関数上位10%の領域を抽出し、その中で「近傍パラメータの成績分散が最小」の点を採用（尖った最高点は棄却）
- パラメータ総数の上限：**戦略あたり6個まで**（Donchian期間、ATR係数k、RS順位閾値、リスク率、タイムストップN、部分利確有無）
- trial_logger への全試行記録と DSR 補正は従来どおり必須

## R4. レジーム判定の二重化

- HMMと並走で **単純レジームフィルタ**（QQQ > 200日MA かつ VIX < 閾値 → 強気）をベースラインに追加
- HMMが単純フィルタにOOSで勝てない場合、HMMを廃止し単純フィルタを採用（複雑さは成果で買う）

## R5. 評価基準の改訂

### 合格ライン（Phase 3 ベースライン、コスト控除後OOS）

| 指標 | 実用最低ライン | 良好 |
|---|---|---|
| Sharpe | ≥ 0.6 | 0.8〜1.0 |
| CAGR | ≥ 10% | 15〜20% |
| MaxDD | ≤ 25% | ≤ 18% |
| **vs QQQ買い持ち** | **Sharpeで上回り、MaxDDで下回る（必須ゲート）** | |
| DSR | > 0 | |
| WF効率 | ≥ 0.5 | |

- QQQゲートに敗ける戦略は他の数値がどれだけ良くても不合格
- 旧目標（Sharpe 1.0〜1.5）は「上振れ期待」に格下げ。IS Sharpe > 2.0 は過学習アラート

## F. 成果分岐フロー（Phase 3 結果で分岐）

```
Phase 3 ベースライン測定（WFA×CPCV、QQQ比較込み）
│
├─ [A] Sharpe≥0.8 かつ QQQゲート合格
│     → Phase 4（alt-dataアブレーション）へ進む
│
├─ [B] Sharpe 0.4〜0.8、または QQQゲート僅差落ち
│     → 簡素化ラダー（1段ずつ実施し再測定、改善したら確定）
│        B1: パラメータを6→4個に削減（タイムストップ・部分利確を固定化）
│        B2: エントリーをDonchianブレイク→「週次の相対強度上位N銘柄
│            ローテーション」に置換（ブレイク待ちを廃止）
│        B3: レジームをHMM→単純フィルタに置換
│     → B1〜B3で[A]水準に達したら Phase 4 へ
│
├─ [C] Sharpe < 0.4、または全変種がQQQゲート不合格
│     → ピボット：週次リレーティブ・ストレングス・ローテーション
│        （実運用実績が最も厚い形態。Dual Momentum系）
│        ・毎週末、ユニバースを6か月リターンでランク付け
│        ・レジーム強気なら上位5〜10銘柄を均等〜ボラ逆比例で保有
│        ・レジーム弱気なら現金化（またはβヘッジ）
│        ・パラメータは3個（ルックバック、保有数、リバランス頻度）のみ
│     → これでもQQQゲート不合格なら [D]
│
└─ [D] 最終フォールバック：システムを「リスク管理オーバーレイ」に転換
       ・コア資産はQQQ/SMH保有（アルファ探索を放棄）
       ・システムの役割はレジーム悪化時の現金化・ヘッジのみ
       　（ボラターゲット＋トレンドフィルタは「DD圧縮」目的なら
       　 エビデンスが最も堅い使い方）
       ・これは failure ではなく、実証結果に基づく合理的な着地点とする
```

## G. 実弾投入までのゲート（全経路共通）

1. **ペーパートレード最低3か月**（サクソのデモ環境＋実シグナル）
   - 実測の1トレード期待値がバックテスト値の50%未満 → 実弾禁止、乖離原因（スリッページ／シグナル遅延／データ差）を特定して戻る
2. **実弾は運用予定資金の25%から**。四半期ごとに実測Sharpe・DDをバックテスト分布と照合し、分布の下位10%を下回ったら増額停止・下位5%で縮小
3. **キルスイッチ**：実運用DDが検証時MaxDDの1.25倍に達したら全ポジション解消し、システム停止・原因分析（これはSPEC.md §6のTier1サーキットブレーカーより優先）

## H. Phase 計画の更新

- Phase 3 を「3a: 単純レジーム＋週次RSローテーション（最小構成）」「3b: フル構成（Donchian＋HMM）」の2本立てに変更。**3aが実質的な[C]ピボット先を先に測っておく**ことで、分岐判断が1回のバックテスト比較で済む
- Phase 4（alt-data）は[A]到達後のみ。到達しない場合はalt-dataに進まない（複雑さの追加で救済しない——これが最大の過学習対策）
