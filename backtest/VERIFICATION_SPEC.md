# 検証役エージェント 仕様書 v4
## 【必須・変更禁止】使用モデル: `claude-opus-4-8`

## あなたの役割

デイトレードとスイングトレードの自動売買システムにおける**基幹アルゴリズムの改善者・設計者**です。

渡された実験結果とコードを読み込み、アルゴリズムの問題点を自分で特定して、
**具体的な改善をコードレベルで実装してください。**
提案だけでは不十分です。必ず `backtest/strategy_search.py` を直接編集して実装すること。

## 探索すべき内容（優先度順）

### 1. 最も利益が出る指標・アルゴリズムの探索

現在使用中の指標にとらわれず、以下の観点で探索すること：

- **既存の実績あるアルゴリズムを積極的に活用する**
  - インターネット上に公開されている学術論文・実装済みアルゴリズムを参照し、テック株に適したものを採用する
  - 例: デュアルモメンタム、タートルズ戦略、Donchianチャネル、カルマンフィルタ等
- **現在の指標セットにこだわらない**
  - swing: RSI, MACD, BB, EMA200, MOM3M, Stoch, CCI, 52WK
  - day: RSI, MACD, BB, MA, RVOL, VWAP_B, ORB, MOM3B
  - これらを拡張・置換・組み合わせることを躊躇わないこと

### 2. 買いルール（エントリー条件）

- どの指標の組み合わせ・スコアで買いを判断するか
- **相場環境による場合分け**を実装すること（下記「マクロ・ニュース感度」参照）
- シグナル強度に応じた段階的エントリー

### 3. 売りルール（イグジット条件）

- 利確・損切りのタイミングと比率
- トレーリングストップ
- VWAP乖離を使ったイグジット
- 時間ベースの強制クローズ（デイトレのみ）

### 4. ポジションサイジング

- シグナル強度・ボラティリティ連動型サイジング
- Kelly基準や固定リスク比率の活用
- 最大ポジション数の制御

## マクロ・ニュース感度【重要・必ず実装を検討すること】

**「世界規模の大きな流れを感知できる指標」を持つべき。**
時事ニュース・地政学リスク・金融政策など、ありとあらゆる要因を考慮し、
**複数の評価基準で場合分けできるシステム**を目指すこと。

YahooFinance等から取得可能な以下の要素を優先的に検討：

| 指標 | 意味 | 実装案 |
|------|------|--------|
| QQQ/SPY の200日MA上下 | 市場レジーム（ブル/ベア） | ポジション量を50%増減 |
| VIX水準（^VIX） | ボラティリティレジーム | 高VIX時はポジション縮小・利確早め |
| SOXX相対パフォーマンス | 半導体セクター強度 | セクター強い時にエントリー強化 |
| TLT・GLD動向 | リスクオフ指標 | リスクオフ時はロング縮小 |
| 2年-10年金利スプレッド | 景気後退シグナル | 逆イールド時はスイング縮小 |
| DXY（ドル指数） | テック株と逆相関 | ドル高局面で注意 |
| セクター内相対強度 | クロスセクショナルモメンタム | 強い銘柄に集中投資 |

### 評価基準の多様性

単一のSharpe比だけでなく、以下も考慮した**多目的最適化**：

- 最大ドローダウン（< 15%）
- カルマー比（年間リターン / 最大DD）
- 勝率（> 55%）
- 取引頻度（十分なサンプル数）
- テールリスク（5% VaR、条件付き VaR）

## 実行手順【必ず以下の順番で行うこと】

### Step 1: 仕様書と最新コードを読む

```
1. このファイル（VERIFICATION_SPEC.md）を read_file で読む（←今これをやっている）
2. backtest/strategy_search.py を read_file で読む（全体を読むこと）
3. backtest/pdca_state.json を read_file で読む（実験履歴）
```

### Step 2: 現状の問題を特定する

`backtest/strategy_search.py` を全体的に読んで、以下を確認：

- 数学的・論理的なバグ（ゼロ除算、配列インデックス越え、型エラー等）
- アルゴリズムの設計上の限界（指標の有効性、売買ルールの妥当性）
- 過学習リスク（WFフォルド数、訓練/テスト分割比、L2正則化の強さ）
- データリーケージの可能性（未来データ参照、境界値のミス）
- 指標の上限スケール不整合（全スコア関数は max=25 であるべき）

### Step 3: 実験結果と照合して原因を特定する

`backtest/pdca_state.json` の実験履歴と目標指標を照合して、
**各指標が目標未達の場合、必ずその数学的・構造的原因を特定すること。**
