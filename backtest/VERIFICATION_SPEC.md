## アルゴリズム方針

- **使えそうなアルゴリズムは積極的に採用**: GA（遺伝的アルゴリズム）、IC+Lift、機械学習、統計的手法など
- **複数の評価基準を使った場合分け**: 相場環境（トレンド相場/レンジ相場）、時事ニュース・市場情勢なども考慮した戦略設計を目指す
- **過学習を防ぐ**: ウォークフォワード検証、OOS（アウトオブサンプル）での安定性を最重要視

## 検証時に必ず確認すること

### 1. 渡された修正内容の検証
- 文法エラー・実行時エラーが発生しないか
- データリーケージ（未来データの混入）がないか
- パラメータの意味と値が整合しているか
- 呼び出し元・呼び出し先への影響（副作用）

### 2. 実験結果からの原因分析
実験結果（Sharpe, WF安定性, 取引数, 勝率など）を見て、以下を調べること：
- なぜその数値になっているのか（コードレベルで原因を特定）
- どのモジュール・関数・定数が問題か
- 改善すれば指標がどう変わるか（定性的な予測）

### 3. 最適化提案
コードの具体的な変更案をdiff形式または説明付きで提示すること。
提案は「確実に効果がある変更」を優先し、根拠を示すこと。

## 現在のコードアーキテクチャ（概要）

```
backtest/
├── strategy_search.py    # メインアルゴリズム（WFフォルド、GA、DOE、アセンブル）
├── fetch_data.mjs        # 価格データ取得（Alpaca/Yahoo Finance）
├── pdca_loop.py          # PDCA自動化ループ
├── pdca_state.json       # PDCA状態管理
├── pdca_trigger.json     # GitHub Actions トリガー
└── phase_artifacts/      # 中間生成物（JSONアーティファクト）
```

### strategy_search.py のフェーズ構成

1. **DOE（田口L18直交表）**: 指標効果の事前スクリーニング → `doe_{mode}.json`
2. **WFフォルド（7〜8分割）**: 各フォルドでGAを走らせてOOS Sharpeを計測 → `wf_{mode}_fold_{N}.json`
3. **Final（全訓練データ）**: 最終モデルをGAで最適化 → `final_{mode}.json`
4. **Assemble**: フォルド結果を集約、WF安定性・ホールドアウト指標を計算 → `strategy_results_{mode}.json`

### 主要パラメータ（現在値）

```python
# GA
GA_POP = 2000, GA_GENS = 500          # swing Final
GA_POP_SWING_WF = 500, GA_GENS_SWING_WF = 150  # swing WFフォルド（時間制約）
GA_POP_DAY = 300, GA_GENS_DAY = 100   # day
GA_L2_LAMBDA = 環境変数（デフォルト0.5）  # swing L2正則化
GA_L2_LAMBDA_DAY = 2.0               # day L2正則化

# 閾値
SWING_BUY_THRESHOLDS = [max(20, t + _TOFF) for t in [30, 35, 40, 45, 50]]
BUY_THRESHOLDS (day) = [max(3, t + _TOFF) for t in [5, 8, 10, 12, 15]]
_TOFF = THRESHOLD_OFFSET環境変数（デフォルト0）

# 最小取引数
MIN_TRADES_OOS = 5  # OOS評価の最小取引数
SWING_MIN_TRADES = 15
MIN_TRADES = 25
```

## 既知の問題（直近の実験で確認済み）

1. **デイトレホールドアウト取引数=4件**: MIN_TRADES_OOS=5より小さいためSharpe=0扱い。根本原因は買い閾値が高すぎること
2. **WF安定性が負**: フォルドをまたぐとOOS Sharpeが大きくばらつく。過学習が疑われる
3. **スイングSharpe改善なし（1.32固定）**: アルゴリズム変更（v13: IC+Lift→GA）の効果が未確認（現在走行中）
4. **THRESHOLD_OFFSET=-20時にBUY_THRESHOLDSが全て3に収束**: 閾値多様性が消える
